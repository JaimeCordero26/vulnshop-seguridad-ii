💥 Explotación en vivo (orden sugerido)

A03 SQL Injection — volcado de usuarios

Pegar en la barra de búsqueda (o en la URL):

' UNION SELECT id,username,password,role,email,address FROM users--

El catálogo muestra los usuarios y sus hashes MD5 en lugar de productos.

📍 server.js L85-98 (consulta con concatenación directa de q).

A03 SQL Injection — bypass de login

  1. En el login, usuario: admin'-- (con el espacio final).
  2. Contraseña: cualquier cosa.
  3. Entra como admin: el -- comenta la verificación de contraseña.

📍 server.js L142-160.

A03 XSS almacenado en comentarios

  1. Abrir un producto y comentar: <script>alert(document.cookie)</script>
  2. Al recargar, el script se ejecuta en el navegador de quien vea el producto.

📍 guardado server.js L110-116; render sin escapar views/product.ejs L25 (<%- %>).

A01 IDOR — perfil ajeno con datos sensibles

  1. Login como daniel / password.
  2. Visitar /profile/1 → perfil del admin con su tarjeta en texto plano.

📍 server.js L212-219.

A01 IDOR — pedidos ajenos + escalada al panel admin

  1. Como daniel, abrir /orders/1 (pedido de otro usuario).
  2. Abrir /admin siendo usuario normal → lista de todos los usuarios, hashes y tarjetas.

📍 server.js L267-273 (pedidos) y L280-285 (admin sin check de rol).

A02 Cryptographic Failures — crackear MD5

  1. Tomar un hash del panel admin o del dump SQLi.
  2. 0192023a7bbd73250516f069df18b500 = admin123 (revertible al instante en CrackStation / rainbow tables).
  3. Mostrar también la tarjeta legible en el perfil y el secreto de sesión hardcodeado en server.js.

📍 db/database.js L17-21; server.js L42-50.

A04 Insecure Design — reset con token predecible

  1. El token es 1000 + id. El admin es id=1 → token 1001.
  2. Visitar /reset?token=1001 y poner nueva contraseña: toma de cuenta sin acceso al correo.

📍 server.js L169-195.

A10 SSRF — importar imagen desde URL

  1. En /admin, campo "Importar imagen desde URL".
  2. Enviar http://127.0.0.1:3000/files (o un recurso interno): el servidor lo trae y devuelve el contenido.
  3. En la nube, http://169.254.169.254/latest/meta-data/ expondría credenciales de instancia.

📍 server.js L288-299.

A08 Subida de archivos sin validación

  1. En el perfil, subir evil.html con <script>alert('xss')</script>.
  2. Abrir /uploads/evil.html: el servidor lo sirve y el navegador ejecuta el script.
  3. Ver el listado de directorio en /files (A05).

📍 server.js L65-72 (nombre original sin sanitizar).

A05 / A06 / A07 / A09 Rápidas

  • A05: /search?q=' muestra stack trace; curl -I / revela X-Powered-By: Express.
  • A06: npm audit lista CVE de lodash 4.17.11 (CVE-2019-10744) y express 4.17.1.
  • A07: fuerza bruta sin bloqueo; registrar con password 1; sin token CSRF.
  • A09: tras los ataques, el servidor no registró ningún evento de seguridad.

🛡️ Mitigaciones (para el Q&A)

VulnCómo se corrige
SQLiConsultas parametrizadas / prepared statements (ya usadas en el resto del código).
XSSEscapar la salida (<%= %>), CSP, sanitización.
IDOR / Access ControlVerificar propiedad del recurso y rol en cada petición (autorización server-side).
Cryptobcrypt/argon2 con salt; cifrar datos sensibles; secreto desde variables de entorno.
Insecure DesignTokens aleatorios criptográficos con expiración y un solo uso.
MisconfigOcultar stack traces, desactivar x-powered-by, sin listado de directorios, sin creds default.
ComponentesActualizar dependencias; npm audit fix; SCA en CI.
AuthRate limiting / lockout, política de contraseñas, regenerar sesión, tokens anti-CSRF.
UploadValidar tipo/tamaño, renombrar, almacenar fuera del webroot.
LoggingRegistrar eventos de seguridad y monitorear/alertar.
SSRFLista blanca de destinos, bloquear IPs internas/loopback, validar esquema.
